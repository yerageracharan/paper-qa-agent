# Security Policy

## Reporting a vulnerability

Please do not publish exploitable details, credentials, private paper contents, or personal data in a public issue or pull request.

Use GitHub's **Security** tab and **Report a vulnerability** flow to send a private report when private vulnerability reporting is enabled for this repository. If that option is unavailable, contact the repository owner privately through their GitHub profile and ask for a secure disclosure route. Do not post the details publicly while arranging contact.

## Include

- A concise description of the affected component and potential impact.
- The affected version or commit SHA.
- Minimal reproduction steps using synthetic or public sample data.
- Any relevant logs with secrets and personal information removed.
- A suggested mitigation, if known.

## Scope and safe handling

- Never attach private research papers, personal data, API keys, tokens, or unredacted environment files.
- Do not test against systems or documents you do not own or have permission to use.
- Findings about answer quality or incorrect citations should normally be filed as product bugs unless they demonstrate a security boundary failure.
- The project is not a secure document vault. Treat uploaded papers and provider prompts according to the privacy properties of the chosen local or hosted provider.
